# 验收口径

## 程序验收

`tests/test_validator.py` 使用自制材料测试真实的约束行为：

- 允许正文完整引文、跨页连续引文、排版空白差异、明确的部分支持与无法核准。
- 拒绝摘要及书目证据、缺字段、引文改字、删除否定词、页码错位、非法跨度、拼接原句、来源变更和版本错配。
- 拒绝复合命题漏核、边界冲突却判直接支持，以及明确标引和建议补引混计。
- 拒绝政策解读冒充正式文件、二手归纳冒充原件验证、非法日期。
- 区分错误、待阅读复核与可交付的否定结果。
- 检查真实来源摘要及目录范围。

测试通过仅说明这些程序检查符合预期，不能据此公布模型语义准确率。

读取阶段增加了 Word 正文、表格、脚注、修订痕迹与引用候选检查，及主稿版本、位置、目标文字校验；PDF 增加缓存、必要才 OCR、不可读页、页边保留、表格下方双栏和内嵌引用标记检查；候选检索与连续字符定位也有测试。

真实项目的读取回归结果记录于 `tests/validation-results.json`，分发包不包含项目原文。62 组既有引文均可连续找回，只证明本次提取保留了这些文本；不能证明全部文献所有页面零误差或模型判定正确。

## 语义验收草案

`tests/fixtures/semantic-cases.json` 包含 15 个自制场景，覆盖直接支持、复合命题、仅摘要相关、对象错配、否定、地域外推、因果升级、政策层级、拼接引文、二手年度归纳、OCR 不可读、补引、跨页和产品范围。

目前这些场景是主 Agent 编写的预期判定草案，**未经过人工标定，未调用插件进行模型评测**。简短上下文也不能替代完整原件，正式测试时须扩展为包含章节、相邻段落和页码的材料包。

下一阶段对每案保存：输入材料版本、预期支持边界、可接受引文与位置、不得判通过的错误、模型实际输出及差异。语义结果由人工或有明确独立性的评审确认；不得把同模型再次检查称为独立专家评审。

优先度高于整体通过率的指标是“错误判通过”：尤其是否定词、范围扩大和政策来源层级问题。另记录漏核、完整句段、正文位置、OCR 页数及输入量。
